## Подключение почты Timeweb (SMTP)

Подключаем ваш ящик `smtp.timeweb.ru:465` к CRM. Все письма (уведомления и документы клиентам) будут уходить с вашего адреса. Входящие читать не будем — это вы делаете в обычном почтовом клиенте.

### Что появится

**1. Уведомления о новых заявках**
- Когда с сайта приходит лид — на `info@alistaru.ru` автоматически уходит письмо: ФИО, телефон, email, источник, сообщение, UTM, ссылка на карточку в CRM.
- Отправитель — ваш ящик Timeweb. Можно ответить клиенту прямо из почты.
- Адрес получателя редактируется в Настройки → Почта (один или несколько через запятую).

**2. Кнопка «Отправить на email» в карточке документа**
- В `/admin/documents` и на карточке сделки рядом с каждым документом — кнопка `Отправить клиенту`.
- Открывается диалог: email клиента (подставляется из связанного клиента), тема, сопроводительный текст (можно вставить из шаблонов), переключатель «приложить файл».
- Файл качается из приватного бакета `documents`, кладётся во вложение и уходит письмом с вашего адреса. Если файл слишком большой (>20 МБ) — автоматически прикладывается подписанная ссылка вместо вложения.

**3. Журнал отправленных писем**
- Новая страница `/admin/emails` со списком: дата, кому, тема, статус (sent/failed), ошибка.
- Видно, ушло ли письмо. Фильтры по статусу и поиск по получателю.

**4. Настройки на странице «Настройки → Почта»**
- Поле «Куда присылать уведомления о заявках» (по умолчанию `info@alistaru.ru`).
- Имя отправителя (например, «Alista»).
- Кнопка «Отправить тестовое письмо» — чтобы сразу проверить, что SMTP работает.
- Тумблер «Уведомлять о новых заявках».

### Технические детали

- Edge-функция `send-smtp-email` (Deno + `denomailer`) шлёт через `smtp.timeweb.ru:465` (TLS).
- Секреты: `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` — попрошу добавить через защищённую форму. **Пароль из чата НЕ используем, его обязательно сменить в Timeweb**.
- Таблица `email_settings` (single row) — куда слать уведомления, имя отправителя, флаг «уведомления вкл/выкл».
- Таблица `email_log` — журнал отправок (recipient, subject, status, error, document_id, created_at). RLS: читают только админы/менеджеры.
- Уведомления о заявках триггерятся через DB-триггер на `leads` → `pg_net.http_post` на edge-функцию `notify-new-lead`, которая дергает `send-smtp-email`. Падение SMTP не блокирует создание лида — ошибка пишется в `email_log`.
- Отправка документа: фронт вызывает `send-smtp-email` с `documentId`. Функция проверяет права (JWT, has_role), скачивает файл из `documents` через service-role, прикладывает, отправляет, пишет в `email_log`.
- Все ответы CORS-совместимы, входные данные валидируются Zod-схемами, антиспам: rate-limit 30 писем/мин на пользователя.

### Что не входит в этот этап

- Чтение входящих по IMAP, привязка ответов к лидам — это отдельная большая работа, можем сделать позже.
- Массовые рассылки — намеренно не делаем (плохо для репутации ящика).
- HTML-конструктор писем — пока простые шаблоны (берутся из уже существующих «Шаблонов сообщений»).

### Порядок действий

1. Создаю таблицы `email_settings`, `email_log` (миграция).
2. Прошу добавить 3 секрета: `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.
3. Пишу edge-функции `send-smtp-email` и `notify-new-lead`, ставлю триггер на `leads`.
4. Делаю UI: вкладку «Почта» в настройках, кнопку «Отправить на email» в документах, страницу `/admin/emails`.
5. Тестируем через «Отправить тестовое письмо».

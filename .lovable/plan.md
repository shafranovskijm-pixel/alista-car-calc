
# План разработки CRM для ALISTA

Согласно ТЗ № 253/2026 нужна CRM, встроенная в админку сайта: заявки, клиенты, сделки, документы, роли, аналитика. Разбиваем работу на 6 этапов — каждый этап даёт законченный рабочий кусок, который можно посмотреть и принять.

## Предварительно: подключение бэкенда

Для CRM нужен бэкенд (база, авторизация, файлы, роли). Включаем **Lovable Cloud** — без него ни авторизация, ни хранение заявок работать не будут. Это первое действие при старте этапа 1.

---

## Этап 1. Фундамент: авторизация и роли

- Включение Lovable Cloud
- Страница `/admin/login` (email + пароль)
- Таблицы: `profiles`, `user_roles` (enum: `admin`, `manager`), security definer `has_role()`
- Защищённый layout `/admin/*` с редиректом неавторизованных
- Базовый сайдбар админки (Заявки / Клиенты / Сделки / Документы / Каталог / Настройки)
- Первый admin создаётся вручную (инструкция в README)

**Результат:** можно войти в админку, видна пустая панель с навигацией.

---

## Этап 2. Модуль «Заявки» + захват с сайта

- Таблица `leads`: ФИО, телефон, email, мессенджер, источник, объект интереса, комментарий, UTM, статус, назначенный менеджер, created_at
- Enum статусов: Новая / В работе / Ожидает оплаты / В пути / Доставлена / Отказ
- Edge function `submit-lead` для приёма заявок с публичных форм (с rate-limit и валидацией)
- Подключение существующих форм сайта (калькулятор, "Получить расчёт", контактная) к этой функции + захват UTM из URL
- Страница `/admin/leads`: таблица с фильтрами (статус, источник, менеджер, период), поиск
- Карточка заявки: просмотр, смена статуса, назначение менеджера, заметки, история изменений

**Результат:** все формы сайта пишут заявки в CRM, менеджеры с ними работают.

---

## Этап 3. Модуль «Клиенты» и «Сделки»

- Таблица `clients`: ФИО, контакты, источник первого обращения, теги
- Автоматическое создание/связывание клиента при поступлении заявки (по телефону/email)
- Карточка клиента: история всех заявок и сделок
- Таблица `deals`: клиент, тип (авто/товар), сумма, маржа, статус воронки, менеджер, документы
- Канбан-воронка сделок (drag-and-drop по статусам)
- Создание сделки из заявки одной кнопкой

**Результат:** единая база клиентов + воронка продаж.

---

## Этап 4. Документы и файлы

- Storage bucket `documents` (приватный, доступ по ролям)
- Таблица `document_templates` (договор, поручение, акт, счёт) — HTML-шаблоны с плейсхолдерами
- Генерация PDF из шаблона с автозаполнением данных клиента/сделки (через edge function)
- Прикрепление произвольных файлов к сделке
- Отправка PDF клиенту по e-mail из карточки сделки (Resend через edge function)

**Результат:** документы генерируются и отправляются прямо из CRM.

---

## Этап 5. Аналитика и уведомления

- Дашборд `/admin`: счётчики заявок, конверсия, средний чек, выручка, прибыль за период
- Отчёт по источникам (UTM/Директ/органика/прямые)
- Отчёт по менеджерам
- Экспорт заявок и сделок в Excel (CSV/XLSX)
- Telegram-бот для уведомлений о новых заявках (edge function + webhook, токен в секретах)
- E-mail уведомления менеджерам через Resend
- Журнал действий пользователей (`audit_log`)

**Результат:** руководитель видит метрики, менеджеры получают пуши.

---

## Этап 6. Каталог авто/товаров через админку

- Таблицы `cars` и `products` с категориями, фото (storage), статусом наличия
- CRUD автомобилей в `/admin/cars` (фото-галерея, характеристики, цена, статус «в наличии / в пути / под заказ»)
- CRUD товаров и категорий в `/admin/products`
- Управление баннерами и текстами главной (`site_content` key-value)
- Публичные страницы каталога (если их ещё нет) с фильтрами + форма «Заказать просчёт» с автоподстановкой марки/модели → заявка в CRM

**Результат:** контент сайта полностью управляется из админки, заявки из карточек авто уходят в CRM.

---

## Технические детали

- **Стек:** существующий (React + Vite + Tailwind + shadcn) + Lovable Cloud (Postgres + Auth + Storage + Edge Functions)
- **Безопасность ролей:** отдельная таблица `user_roles` + `has_role()` security definer + RLS на всех таблицах (никогда не храним роль на profiles)
- **RLS-политики:** менеджер видит только свои заявки/сделки, админ — все
- **Каждая `CREATE TABLE` в миграциях сопровождается `GRANT` + `ENABLE RLS` + политиками**
- **Секреты** (Telegram bot token, Resend API key) — через Lovable Cloud secrets, не в коде
- **PDF-генерация** — на стороне edge function (например, через pdf-lib)
- **Без ломки текущего сайта:** все новые маршруты под `/admin/*`, публичные формы только дополняются обработчиком отправки
